# SoftLicence.SDK 1.1.13 — Structured error contract and consumer integration guide

**Document scope:** SDK version `1.1.13`

**Server contract:** error contract version `1`

**Audience:** maintainers integrating SoftLicence.SDK into T-IA Connect, YOUR_APP_NAME, or another .NET application

SoftLicence server responses may include the following headers on a failed activation, status check, trial request, or deactivation:

- `X-SoftLicence-Error-Contract: 1`
- `X-SoftLicence-Error-Code: <CANONICAL_CODE>`
- `X-SoftLicence-Correlation-Id: <OPAQUE_ID>`

Error-code values are canonical ASCII identifiers and are compared with ordinal, case-sensitive semantics. Public messages remain localizable and must never be parsed when a structured code is present. A missing header identifies a legacy server; SDK 1.1.13 retains the historical text fallback for that case only. A present but unknown, empty, or duplicated code fails closed as `ServerError`.

## Activation mapping in SDK 1.1.13

| Server codes | SDK result |
| --- | --- |
| `INVALID_LICENSE_KEY` | `InvalidKey` |
| `LICENSE_DISABLED`, `PARTNER_INVALID`, `BANNED`, `COMPONENT_BANNED` | `LicenseDisabled` |
| `LICENSE_EXPIRED` | `LicenseExpired` |
| `SEAT_LIMIT`, `MAX_DAILY_ACTIVATIONS_REACHED` | `MaxActivationsReached` |
| `VERSION_NOT_ALLOWED`, `UPDATE_REQUIRED` | `VersionNotAllowed` |
| `APP_UNKNOWN` | `AppNotFound` |
| Any other structured value | `ServerError` |

The exact server value and opaque correlation identifier are available through `ActivationResult.ServerErrorCode` and `ActivationResult.CorrelationId`. `UsedLegacyErrorFallback` is true only when the response came from a server without the structured code header, allowing applications to measure remaining legacy-server use without recording response bodies.

Status and deactivation failures expose the same support fields through `LicenseStatusResult` and `DeactivationResult`. Their existing success/status behavior remains unchanged for source and binary compatibility.

## Compatibility and deprecation

The HTTP status and existing localized body remain available to earlier SDKs. Structured JSON failures expose the canonical `message` property and retain the historical `errorMessage` alias throughout contract version `1`. The alias is deprecated but cannot be removed without a separately announced breaking contract version. Consumers must ignore unknown response headers and must not infer business meaning from the correlation identifier.

The legacy text fallback is scheduled for review only after supported applications have adopted SDK 1.1.13 or later and server telemetry shows that the old contract is no longer needed. Its removal requires a separately announced SDK release.

## Security and support

Correlation identifiers are generated by the server request pipeline. They are opaque and contain no license key, token, customer email, or hardware identifier. Support logs may store the correlation identifier and canonical error code, but must not store full error response bodies or licensing secrets.

HWID V2 remains an observation-only signal in SDK 1.1.13. This error-contract change does not alter hardware identity, activation authority, seat allocation, or fallback behavior.

## Consumer integration checklist

Use this checklist when adopting SDK 1.1.13 in T-IA Connect, YOUR_APP_NAME, or another application:

1. Update every direct `SoftLicence.SDK` package reference together, including recovery, installer, plugin SDK, or embedded-DLL projects.
2. Remove stale hard-coded NuGet DLL paths and update embedded resource paths when the application embeds the SDK assembly.
3. Keep the existing handling of `ActivationErrorCode`; it remains source-compatible. Optionally use `ServerErrorCode` for exact internal diagnostics and `CorrelationId` for a user-safe support reference.
4. Never display raw server codes as translated customer messages and never log full response bodies, license keys, or hardware identifiers.
5. Treat `UsedLegacyErrorFallback == true` as a bounded diagnostic signal that the contacted server has not supplied the structured contract. Do not reinterpret a present but unknown structured code.
6. Validate activation, trial, status, deactivation, offline/cache behavior, recovery, and any embedded assembly loading on the application's supported runtimes.
7. Confirm that `HardwareId` remains the contractual identity and `HardwareIdV2` remains observation-only. Do not change seats, cache keys, or migration logic as part of this SDK adoption.

For T-IA Connect specifically, update both `TiaPortalApi.Core` and `TiaPortalApi.Recovery`; Recovery currently embeds the exact NuGet assembly and therefore requires an explicit embedded-resource version update and recovery-path validation.
